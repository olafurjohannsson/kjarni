# Kjarni from C++

## Quickstart

Four commands, no build system and no package manager. Linux x86_64 shown; the
[releases page](https://github.com/olafurjohannsson/kjarni/releases/latest) has
macOS and Windows builds.

```bash
mkdir kjarni-quickstart && cd kjarni-quickstart
curl -sL https://github.com/olafurjohannsson/kjarni/releases/latest/download/kjarni-x86_64-linux.tar.gz | tar xz
curl -sO https://raw.githubusercontent.com/olafurjohannsson/kjarni/main/crates/kjarni-ffi/examples/cpp/hello.cpp
g++ -std=c++23 hello.cpp -I. -L. -lkjarni_ffi -Wl,-rpath,'$ORIGIN' -o hello && ./hello
```

```
related:   0.5510
unrelated: -0.0630
```

The tarball holds the shared library, both headers and the CLI, all at the top
level. The model downloads on first run and is cached under `~/.cache/kjarni`.

On macOS the library is `libkjarni_ffi.dylib` and the rpath flag becomes
`-Wl,-rpath,@loader_path`. Needs a compiler with C++23 `<print>`: GCC 14+ or
Clang 17+.


Two headers, one shared library, and the model runs inside your process. Useful
where a network call is not an option: desktop software shipped to customers,
industrial and medical systems, field tools that work without connectivity.

- **`kjarni.h`** — the C ABI, generated by cbindgen. Usable from C, or from C++ if
  you want to manage lifetimes yourself.
- **`kjarni.hpp`** — a header-only C++23 wrapper. Handles are `unique_ptr`s with the
  matching C deleters, arrays are move-only owners, and errors are
  `std::expected` values. Use this unless you have a reason not to.

```cpp
#include "kjarni.hpp"

auto embedder = kjarni::Embedder::create({.model = "minilm-l6-v2"});
if (!embedder) return std::println("{}", embedder.error().message()), 1;

auto a = embedder->encode("How do I get my money back?");
auto b = embedder->encode("What is your refund policy?");

std::println("{:.4f}", kjarni::cosine(*a, *b));   // 0.5510
```

Nothing is freed by hand. `Embedding` owns its `KjarniFloatArray`, `Embedder` owns
its handle, and both release on scope exit — including when an early `return` skips
the rest of a function.

## Building

```bash
cmake -B build -DKJARNI_LIB_DIR=/path/to/lib
cmake --build build
./build/example
```

Or directly:

```bash
g++ -std=c++23 example.cpp -I../../include -L/path/to/lib -lkjarni_ffi -o example
```

`example.cpp` covers embeddings, batch encoding, classification, reranking, and chat
with token streaming. Running it prints:

## The API

Every fallible call returns `kjarni::Result<T>`, which is
`std::expected<T, kjarni::Error>`. Check it, or use `value_or`, or
`and_then` — whatever suits. The error carries the library's own message, captured
at the point of failure rather than read later from the global slot.

```cpp
auto chat = kjarni::Chat::create({
    .model = "llama3.2-3b-instruct",
    .system_prompt = "You are terse.",
});

auto reply = chat->send("Explain RAG in one sentence.",
                        kjarni::Generation::greedy(256));
```

Streaming takes any callable. Returning `false` stops generation immediately rather
than running to completion and discarding the result:

```cpp
auto ok = chat->stream("Write a haiku.", [](std::string_view token) {
    std::print("{}", token);
    return true;
});
```

Batch encoding is one call and markedly faster than looping:

```cpp
std::vector<std::string> docs{"first", "second", "third"};
auto vectors = embedder->encode(docs);        // vector<vector<float>>
```

Reranking returns indices into your input, so you keep your own IDs and metadata:

```cpp
auto ranked = reranker->rerank(query, docs);
for (const auto& r : *ranked) std::println("{:.2f} {}", r.score, docs[r.index]);
```

## Requirements

**C++23**, for `std::expected`. Everything else in the header is C++20. If you are
stuck on C++20, replacing `std::expected` with `std::variant` or exceptions is the
only change needed.

Tested with GCC 15. Clang 17+ and MSVC 19.38+ should work.

## A note on warnings

GCC's `-Wextra` reports `-Wmissing-field-initializers` when you use a designated
initialiser that omits fields — which is exactly how the option structs are meant to
be used. The warning is unhelpful for C++20 designated initialisers; the CMake build
turns it off for this target. The header itself is warning-clean under `-Wall
-Wextra`.

## Memory

The wrapper is checked under AddressSanitizer and UndefinedBehaviorSanitizer with
leak detection enabled, and reports nothing:

```bash
g++ -std=c++23 -g -fsanitize=address,undefined example.cpp \
    -I../../include -L/path/to/lib -lkjarni_ffi -o example_asan
ASAN_OPTIONS=detect_leaks=1 ./example_asan
```

If you use `kjarni.h` directly instead, the rules are: anything Kjarni allocates,
Kjarni frees, and each type has its own function — `kjarni_float_array_free`,
`kjarni_class_results_free`, `kjarni_string_free`, and so on.

## What's available

Embeddings, classification, reranking, indexing, search and chat. Transcription,
summarization and translation exist in the engine and on the command line but are
not in the C ABI yet.

## Getting the library

Download the archive for your platform from
[releases](https://github.com/olafurjohannsson/kjarni/releases), or build it:

```bash
cargo build --release -p kjarni-ffi     # target/release/libkjarni_ffi.so
```

Models download on first use and cache locally; after that everything is offline.

## Regenerating the C header

`kjarni.h` is generated. After changing the FFI:

```bash
cd crates/kjarni-ffi
cbindgen --config cbindgen.toml --crate kjarni-ffi --output include/kjarni.h
cp include/kjarni.h dist/include/kjarni.h
```
